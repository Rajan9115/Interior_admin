# MAMA INTERIOR CMS — Deployment, Security & Operations Manual

This document provides complete, authoritative instructions for deploying, operating, securing, and maintaining the **MAMA INTERIOR Content Management System** in staging and production environments.

---

## 1. Architecture & URL Separation

In accordance with the mandatory architecture decisions, the system operates as two decoupled Next.js applications deployed to separate domains:

| Application | Production Target URL | Directory | Responsibility |
|---|---|---|---|
| **Public Website** | `https://mamainterior.in` | `website/` | Customer-facing portfolio, zero database credentials, zero Cloudinary secrets |
| **Admin CMS & API** | `https://admin.mamainterior.in` | `admin/` | Single-owner dashboard & backend Route Handlers (`/api/v1/...`) |

---

## 2. Environment Variables Configuration

Create independent `.env.production` files for each application. **Never commit actual production secrets to source control.**

### A. Admin CMS & Backend API (`admin/.env.production`)
```bash
# Node Environment
NODE_ENV="production"
PORT=3001

# PostgreSQL Database (Transaction connection pooler or direct connection)
DATABASE_URL="postgresql://mama_admin:SECURE_PASSWORD@postgres.internal:5432/mamainterior_prod?schema=public&sslmode=require"

# Cloudinary Storage Credentials (Authoritative, Server-Side Only)
CLOUDINARY_CLOUD_NAME="your_cloud_name"
CLOUDINARY_API_KEY="your_api_key"
CLOUDINARY_API_SECRET="your_server_only_secret"
CLOUDINARY_ROOT_FOLDER="mama-interior"

# Public Website URL (For CORS and On-Demand Revalidation)
PUBLIC_WEBSITE_URL="https://mamainterior.in"
ADMIN_DASHBOARD_URL="https://admin.mamainterior.in"

# Cache Revalidation Secret (Shared between admin and website)
REVALIDATION_SECRET="a_strong_64_character_random_hex_token"
```

### B. Public Website (`website/.env.production`)
```bash
# Node Environment
NODE_ENV="production"
PORT=3000

# Backend Public API URL (Accessible over HTTPS or internal service mesh)
NEXT_PUBLIC_API_URL="https://admin.mamainterior.in/api/v1/public"

# Cache Revalidation Secret (Must match REVALIDATION_SECRET in admin)
REVALIDATION_SECRET="a_strong_64_character_random_hex_token"
```

## 3. Database Migration & Initial Seed

### A. Apply PostgreSQL Migrations
Execute from the `admin/` directory:
```bash
npx prisma migrate deploy
```

### B. Seed the 4 Protected Core Trades
Seeds the architectural trade categories (`electrical`, `carpentry`, `painting`, `ceiling`):
```bash
npx prisma db seed
```

## 4. Single-Owner Bootstrap Procedure

There is **no public signup route**. The sole contractor/owner account is securely bootstrapped via the server-side CLI script:

```bash
cd admin
npm run bootstrap:owner
```

Or execute directly with custom initial credentials:
```bash
OWNER_EMAIL="owner@mamainterior.in" OWNER_PASSWORD="YourStrongInitialPassword123!" OWNER_NAME="Owner Name" npx tsx scripts/bootstrap-owner.ts
```

*Note: Passwords are automatically hashed with bcrypt using 12 rounds. Once bootstrapped, the owner can log in at `https://admin.mamainterior.in/login`.*

## 5. Cloudinary Media Configuration

1. In Cloudinary Dashboard, ensure the configured Cloudinary account is active.
2. Under **Settings > Upload**, ensure unsigned uploads are **disabled**. All uploads must use authenticated signatures generated by `POST /api/v1/admin/media/signature`.
3. Allowed image types: `image/jpeg`, `image/png`, `image/webp` (Max 15 MB).
4. Allowed video types: `video/mp4`, `video/quicktime` (Max 100 MB).
5. All assets are automatically prefixed with `mama-interior/projects` or `mama-interior/general` on the server. Folder traversal attempts are stripped.

---

## 6. On-Demand Cache Revalidation

When a project is published, unpublished, archived, or reordered:
1. Admin triggers a call to `website/api/revalidate`.
2. Public website revalidates tagged routes:
   - `projects`: The public project catalog listing.
   - `project-[slug]`: The specific project detail page.
   - `homepage`: The featured portfolio grid.
3. If the backend is temporarily offline, the public website automatically falls back to bundled static data so customer pages never crash.

## 7. Automated Backups & Disaster Recovery

### A. Create Automated Database Backup
Run the backup script (runs via scheduled cron or task scheduler):
```powershell
powershell -File scripts/backup-db.ps1
```
Backups are dumped as compressed SQL dumps in `./backups/mamainterior_backup_YYYYMMDD_HHMMSS.sql`.

### B. Restore Database from Backup
```powershell
powershell -File scripts/restore-db.ps1 -BackupFile ./backups/mamainterior_backup_20261111_140000.sql
```
